# Internationalization

English (`en-US`) is the default language of the whole system. Every user-facing string is a translation key.

## Dashboard

- Catalogues: `packages/translations/locales/<locale>.json` (nested keys, ICU message syntax).
- Library: `next-intl` without locale-prefixed routes. The locale is resolved per request from the `NEXT_LOCALE` cookie, otherwise `en-US` (the browser language is deliberately not used).
- Signed-in users: the saved preference (`dashboard_users.locale`) is applied on load; changing the language saves it and re-renders immediately (`router.refresh()`), no reload or restart.
- Missing keys fall back to English (`getMessages()` deep-merges each catalogue over `en-US`).
- Type safety: `src/global.d.ts` types messages against `en-US.json`, so using an unknown key fails `tsc`.
- Pluralization and variables: ICU, e.g. `"{count, plural, =0 {No players} one {# player} other {# players}}"`.
- Numbers, dates and relative times use `useFormatter()` with the active locale and the user's time zone (`mnm_tz` cookie, from the account preference or the browser).

## Adding a language

1. Copy `packages/translations/locales/en-US.json` to e.g. `fr-FR.json`, set `meta.locale`, translate.
2. Register it in `packages/translations/src/index.ts` (`bundledCatalogs`) and `packages/shared-types/src/locales.ts` (`BUNDLED_LOCALES`).
3. Copy `packages/translations/minecraft/en-US.yml` to `fr-FR.yml` for plugin messages.
4. Run `npm run translations:validate`. It fails on unsafe content, unknown keys or broken placeholders and reports missing keys.
5. After deployment the language appears in *Settings → Languages*, where it can be enabled, disabled or made the default.

Administrators can see missing-key counts and export catalogues (`GET /api/i18n/catalogs/:locale`). Languages can be added and catalogues imported at runtime (table `translation_catalogs`, validated like bundled files); the dashboard merges imported texts over the bundled catalogue and picks up changes within 30 seconds. See [Configuration management](configuration.md#translation-management).

## Minecraft plugins

`packages/translations/minecraft/<locale>.yml` holds flat, dot-separated keys with `{placeholder}` variables and MiniMessage formatting. The plugins (Phase 2) will ship these files, use the network language by default and optionally each player's client locale.
